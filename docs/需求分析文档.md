## 1. 项目概述

### 1.1 项目定位

MJFLY 是一款基于 Android 平台的无人机控制应用，支持通过 **WiFi 直连** 控制 DJI Tello 无人机。通过手机连接无人机 WiFi 热点，使用 UDP 协议发送控制命令并接收实时状态数据，实现起飞、降落、虚拟摇杆操控等功能。

同时保留 **DJI SDK V5 5.17.0** 框架集成，为后续扩展更多 DJI 机型支持提供基础。

### 1.2 目标用户

- DJI Tello 无人机用户
- 大疆无人机开发者/飞手
- 需要自定义移动端飞控界面的技术团队
- 学习 Android 高级开发与无人机 SDK 集成的开发者

### 1.3 运行环境

| 项 | 要求 |
|---|---|
| 操作系统 | Android 7.0+ (API 24+) |
| CPU 架构 | arm64-v8a |
| 连接方式 | WiFi 直连（手机连接无人机热点） |
| 网络要求 | 无需互联网（SDK 注册时需要） |
| 硬件要求 | 支持 WiFi |

### 2.2 飞行控制需求详述

#### 2.2.1 一键起飞

- **触发条件**：WiFi 已连接到 Tello 热点
- **实现方式**：UDP 发送 `takeoff` 命令到 192.168.10.1:8889
- **响应处理**：等待 Tello 返回 `ok` 表示成功
- **安全约束**：起飞前确认降落区域安全
- **文件位置**：`TelloFlightControlRepository.kt:takeOff()`

#### 2.2.2 一键降落

- **触发条件**：飞行器处于飞行状态
- **实现方式**：UDP 发送 `land` 命令
- **响应处理**：等待 Tello 返回 `ok` 表示成功
- **文件位置**：`TelloFlightControlRepository.kt:land()`

#### 2.2.3 返航 (RTH)

- **Tello 限制**：Tello 不支持 GPS 返航功能
- **替代方案**：执行降落命令代替返航
- **文件位置**：`TelloFlightControlRepository.kt:startRTH()`

#### 2.2.4 虚拟摇杆控制

- **控制命令**：`rc <left_right> <forward_backward> <up_down> <yaw>`
- **摇杆映射**：
  - 左摇杆：油门 (Throttle → up_down) + 偏航 (Yaw → yaw)
  - 右摇杆：俯仰 (Pitch → forward_backward) + 横滚 (Roll → left_right)
- **发送频率**：20Hz（每 50ms 一次）
- **数据范围**：-100 ~ +100（应用层归一化 -1.0 ~ +1.0 后乘以 100）
- **特点**：rc 命令不需要等待响应（高频发送场景）
- **文件位置**：`TelloFlightControlRepository.kt:sendVirtualStickData()`

#### 2.2.5 紧急停止

- **功能**：立即禁用虚拟摇杆（发送 `rc 0 0 0 0`）+ 触发降落
- **使用场景**：突发状况时快速响应
- **文件位置**：`ControlViewModel.kt:emergencyStop()`

### 2.3 实时状态监测需求详述

#### 数据来源

通过 UDP 端口 8890 接收 Tello 主动推送的状态字符串，解析为结构化数据。

#### 状态数据字段

| 字段 | Tello 键名 | 说明 |
|------|-----------|------|
| 电池电量 | `bat` | 百分比 0-100 |
| 低温 | `templ` | 芯片低温 (°C) |
| 高温 | `temph` | 芯片高温 (°C) |
| 飞行高度 | `h` | 相对高度 (cm) |
| ToF 距离 | `tof` | 对地距离 (cm) |
| 气压计 | `baro` | 气压计高度 (m) |
| 飞行时间 | `time` | 已飞行秒数 |
| 俯仰角 | `pitch` | 度 |
| 横滚角 | `roll` | 度 |
| 偏航角 | `yaw` | 度 |
| X 轴速度 | `vgx` | cm/s |
| Y 轴速度 | `vgy` | cm/s |
| Z 轴速度 | `vgz` | cm/s |
| X 轴加速度 | `agx` | 0.001g |
| Y 轴加速度 | `agy` | 0.001g |
| Z 轴加速度 | `agz` | 0.001g |

#### 数据接收实现

- **监听方式**：`DatagramSocket` 绑定 UDP 8890 端口
- **超时设置**：3 秒超时后继续循环监听
- **解析方式**：分号分隔 → 冒号键值对 → TelloState 数据类
- **文件位置**：`TelloStateReceiver.kt`

### 2.4 WiFi 连接检测需求详述

#### 检测机制

- **检测方式**：通过 `WifiManager` 获取当前 WiFi SSID
- **匹配规则**：SSID 前缀匹配（支持 TELLO/DJI Mini/Mavic/Air 等前缀）
- **检测频率**：每 2 秒一次
- **状态流**：通过 `StateFlow<Boolean>` 驱动 UI 更新
- **文件位置**：`WifiConnectionDetector.kt`

#### 支持的 SSID 前缀

```
TELLO, DJI Mini 3 Pro, DJI Mini 4 Pro, DJI Mini 3, DJI Mini 2,
MavicMini, Mavic Air, Air2S, Mavic3, Mavic 3, Avata, DJI FPV,
DJI Air, DJI Mavic, Mavic2, Mini 4K, DJI Neo
```

## 3. 架构设计

### 3.1 架构模式

采用 **MVVM (Model-View-ViewModel) + Repository** 模式：

```
View (Fragment) → ViewModel → Repository Interface → Repository Impl → UDP/DJI SDK
```

### 3.2 分层职责

| 层次 | 职责 | 技术 |
|------|------|------|
| **UI Layer** | 展示界面、用户交互、权限请求 | Fragment、ViewBinding、Navigation |
| **ViewModel Layer** | 状态管理、业务逻辑、协程调度 | ViewModel、StateFlow、Coroutine |
| **Repository Layer** | 数据抽象、UDP/SDK 调用封装、错误处理 | 接口定义、Tello UDP 实现 |
| **数据源层** | Tello 状态接收、WiFi 检测、SDK 管理 | TelloStateReceiver、WifiConnectionDetector |
| **通信层** | UDP 文本协议 (Tello) / DJI SDK V5 | DatagramSocket、SDKManager |

### 3.3 依赖注入

使用 **Hilt 2.52** 进行依赖注入：

```kotlin
@AndroidEntryPoint          // Fragment/Activity 注入点
@HiltViewModel              // ViewModel 注入
@Inject constructor(...)    // 构造函数注入
@Singleton                  // 单例作用域
@Module @InstallIn(SingletonComponent::class)
```

### 3.4 数据流设计

所有状态通过 Kotlin **StateFlow** 驱动：

```
TelloStateReceiver (UDP 8890 → MutableStateFlow<TelloState>)
  → AircraftRepositoryImpl (combine/map → AircraftStatus/FlightTelemetry)
    → ControlViewModel (combine connectionState + status)
      → ControlUiState (StateFlow)
        → ControlFragment (collectIn / lifecycleScope)
          → UI 更新
```

### 3.5 SDK 集成设计

**WiFi 模式初始化**：

1. **`DjiSdkManager.initialize()`**：启动 WiFi 连接状态监控（每 2 秒检测）
2. **SDK 注册**：调用 `SDKManager.getInstance().init()` + `registerApp()`
3. **连接状态**：WiFi SSID 匹配 → `ConnectionState.Connected(ssid)`

**Tello 通信流程**：

```
App 启动 → WifiConnectionDetector 开始监控
  → 检测到 TELLO SSID → ConnectionState.Connected
    → 用户操作 → TelloFlightControlRepository.sendCommand()
      → UDP 发送到 192.168.10.1:8889
        → 接收响应 (ok/error)
```

## 4. 技术决策

### 4.1 为什么选择 WiFi 直连而非 USB OTG？

- **Tello 限制**：DJI Tello 仅支持 WiFi 连接，无法使用遥控器
- **便捷性**：无需额外硬件（USB OTG 线、遥控器），手机直接连接
- **开发效率**：UDP 文本协议简单直观，易于调试和测试
- **适用范围广**：多款 DJI WiFi 无人机使用相同连接方式

### 4.2 为什么使用 UDP 文本协议？

- **Tello SDK 标准**：Tello 官方 SDK 即为 UDP 文本协议
- **低延迟**：UDP 无连接，适合实时控制场景
- **高频发送**：虚拟摇杆 20Hz 发送无需连接确认开销
- **简单可靠**：命令-响应模式，易于错误处理

### 4.3 为什么使用 StateFlow 而非 LiveData？

- **原生 Kotlin 支持**：与 Coroutine 生态无缝集成
- **操作符丰富**：`combine`、`map`、`filter` 等操作符简化数据流处理
- **线程安全**：默认在主线程发射和收集

### 4.4 为什么仅支持 arm64-v8a？

- **DJI SDK V5 限制**：官方仅提供 arm64-v8a 原生库
- **设备覆盖**：Android 7.0+ 的无人机控制设备均为 64 位 ARM
- **APK 体积**：减少不必要的架构支持，缩小 APK 大小

## 7. 安全约束

### 7.1 飞行安全

- 紧急停止按钮可在异常时快速响应
- 所有飞行操作通过 `Result` 类型返回成功/失败状态
- Tello SDK 模式需首先发送 `command` 命令激活
- UDP 命令超时设置 5 秒，防止无限等待

### 7.2 权限安全

启动时自动检查并申请以下权限：
- 网络：INTERNET, ACCESS_NETWORK_STATE, ACCESS_WIFI_STATE, CHANGE_WIFI_STATE
- 定位：ACCESS_FINE_LOCATION, ACCESS_COARSE_LOCATION（WiFi SSID 获取需要）
- 存储：READ/WRITE_EXTERNAL_STORAGE
- 其他：FOREGROUND_SERVICE

### 7.3 通信安全

- Tello 通信通过本地 WiFi 网络，无外部暴露
- UDP 命令端口仅发送到 192.168.10.1（Tello 固定 IP）
- WiFi 直连模式下无互联网访问

## 8. 已知限制

| 限制项 | 说明 | 原因 |
|--------|------|------|
| 无 GPS 返航 | Tello 不支持 RTH | Tello 硬件限制，无 GPS 模块 |
| 无相机控制 | Tello 基础版无独立相机控制 | Tello SDK 限制 |
| 无图传显示 | 未实现视频流解码 | 需接入 Tello 视频流 (UDP 11111) |
| 飞行距离 | 受 WiFi 信号范围限制 | WiFi 直连模式物理限制 |
| 无避障 | Tello 无避障传感器 | 硬件限制 |
| 仅 arm64-v8a | 不支持 x86/armeabi-v7a | DJI SDK 仅提供 arm64 原生库 |
